## What this is

EZMiner is a **Minecraft Forge 1.7.10** chain-mining mod for the **GregTech: New Horizons (GTNH)** modpack. It runs on both client and server, and uses **Mixin** minimally (fortune-uncap, fast-harvest, and the pause-menu "Mod Options" replacement).

## Build & Validate

```bash
./gradlew spotlessApply build
```

- **No tests exist** — validation is a successful build (Spotless `apply` + `check` + Checkstyle + reobf + jar).
- Build uses the GTNH convention plugin with **Jabel** (Java 17 syntax targeting JVM 8) and **Mixins** (`usesMixins = true`, early config `mixins.EZMiner.json`, late config `mixins.EZMiner.late.json`).
- The Mixin annotation processor generates `build/tmp/mixins/mixins.EZMiner.refmap.json`; vanilla/FML-targeted mixins use MCP names and rely on it (production remap).
- Note: `gtnh.settings.blowdryerTag=0.2.2` (Blowdryer) fetches Spotless config from GitHub raw; if the Gradle JVM cannot reach it, build with `-Pgtnh.settings.blowdryerTag=LOCAL` and put the three files (`spotless.gradle`, `spotless.importorder`, `spotless.eclipseformat.xml`) in `gtnhShared/`.

## Architecture overview

- **Legacy layer** (`core/`, `client/`, root package): `Manager` (per-player event wiring), `BaseOperator` (server-tick harvest batching), `core/founder/` (`BasePositionFounder` hierarchy), HUD/render/key input.
- **Chain subsystem** (`chain/`): `state/` (per-player `ChainPlayerState`, `ChainStateService`), `lifecycle/`, `planning/` (`ChainPlanner` scaffold, `ChainPreCalcEngine`/`Cache`), `execution/` (harvest executors, `ChainDropCollector`, `XPDropHandler`, special-mode handlers), `mode/`, `network/`, `watchdog/`.
- **Mixin** (`mixin/early/`, `mixin/ILateMixinPlugin`): fortune uncap, `MixinItemInWorldManager` fast harvest, `MixinGuiIngameMenu` (pause-menu "Mod Options" replacement).
- **Compat** (`compat/`): GT5, TinkersConstruct, Natura, Witchery, Bandit, VisualProspecting, EndlessIDs-aware writes.

## Harvest / world-mutation paths (server thread)

Three paths exist; all mutation runs on the server thread:

1. **Per-block fast path** — `BlockHarvestActionExecutor.execute()` → mixin `ezminer$tryHarvestBlockFast` → `World.setBlock(..., air, 0, 2)` (flag 2 = client update, no neighbor notify).
2. **Batch chunk-cached path** — `ChunkCachedHarvester.harvestNext()` → `ChunkBlockWriteHelper.writeAirToEbs()` (direct `ExtendedBlockStorage.func_150818_a`), then `markBlockForUpdate` + height-map update. **Metadata is always zeroed** there to avoid "air + stale GT meta" blocks (`name.0`).
3. **TE path** — vanilla `tryHarvestBlock` for `block.hasTileEntity(meta)`.

**Neighbor notifications** (`onNeighborBlockChange`) are fired **by default** after each harvest batch, deduplicated, so water/sand/gravel/cactus/tall-grass react (flow / fall / break / pop) instead of floating next to a mined cavity. Controlled by `Config.notifyNeighborsOnChainBreak` (default **on**; cost is surface-proportional, not volume — turn off only for max-FPS). Note: vanilla *grass blocks* above a mined void stay floating even in normal mining (no neighbor reaction exists for them); grass *plants* (`tallgrass`, `BlockBush`) DO pop via `onNeighborBlockChange` and are covered by this fix.

**Tree felling**: `LogFounder` + `ChunkBlockWriteHelper.flagNeighbouringLeavesForDecay()` (called for removed wood blocks) flags adjacent leaves via vanilla `beginLeavesDecay`, so canopies decay like vanilla instead of floating.

**CoFH Core water**: CoFH Core's ASM replaces water with `BlockTickingWater extends BlockDynamicLiquid`, whose `onNeighborBlockChange` is a no-op for water. `CoFHWaterBridge.ensureWaterFlowUpdate()` (called after every notified non-air neighbour in `notifyBatchNeighborChange`) **deterministically fills the vacated hole below any notified water neighbour** (flowing water level 8, flag 3 — the vanilla `func_149813_h` downward flow) and also schedules the neighbour's flow tick, so water settles with or without CoFH — `instanceof BlockDynamicLiquid` only, no CoFH compile dependency.

**Grass-plant/bush family**: tall grass/flowers/ferns/saplings (`BlockBush` subclasses) should pop when their support is mined. `BushSupportBridge.popIfUnsupported()` re-verifies `canBlockStay` after the notification and drops+clears a still-present unsupported plant, mirroring vanilla `BlockBush.checkAndDropBlock` — immune to mods that co-opt `onNeighborBlockChange`.

**Hodgepodge interaction**: Hodgepodge replaces `ChunkProviderServer`'s `LongHashMap` with an owner(server)-thread `ServerThreadLongHashMap` (background reads use snapshots) and its `MixinWorld_PreventChunkLoading` short-circuits neighbor notifications on unloaded chunks. All EZMiner world writes/notifications are server-thread-only (never background), so no new off-thread warnings are introduced; `Config.suppressHodgepodgeWarnings` filters the pre-existing founder-thread logs.

## Network threading

1.7.10 `SimpleNetworkWrapper` dispatches server handlers on the netty IO thread. `MainThreadEnforcer.guardedNull()` now **actually defers** server-mutating handlers to the next server tick via `MainThreadEnforcer.DEFERRED`, drained by `PlayerManager.onServerTick`. `PlayerManager.managers` is a `ConcurrentHashMap` for the same reason.

## Public API for other mods

`com.czqwq.EZMiner.api.EZMinerAPI` — programmatic chain control:

- Server (must run on server thread): `setChainKeyHeld(UUID, boolean)`, `startChain(UUID, Vector3i)`, `setMainMode/setBlastSubMode/setChainSubMode/setSpecialSubMode(UUID, int)`, `setMode(UUID, main, blast, chain, special)` (‑1 = untouched).
- Queries: `isKeyHeld(UUID)`, `isOperateActive(UUID)`, `isActive(UUID)`, `getChainActivationMode()`.
- Client: `pressChainKeyClient()/releaseChainKeyClient()` (send `PacketKeyState`), `applyModeClient(...)` (send `PacketChainModeSwitch`), `setChainActivationMode(int)`.
- Server-side calls are authoritative writes (equivalent to receiving trusted packets); client calls only send C→S packets, keeping server authority.

## Coding conventions

- Root package `com.czqwq.EZMiner`; run `./gradlew spotlessApply` before committing (Google Java Format).
- New server config field: declare in `Config` (server section), load in `loadServerOnlyInternal`, save in `saveServerConfig`, sync via `PacketServerConfig` + `applyServerRuntimeConfig`, save via `PacketSaveServerConfig`, and add a GUI row (Server tab; when appending at the end bump `SERVER_CONTENT_ROWS` and update `isSectionBreak`/`getRowLabelKey`/`initGui`/`actionPerformed`/`updateScrolledPositions`/`drawServerTab`/`updateTabVisibility`/`applyAndSaveServerConfig` at the new row + `lang`).
- New network packet: register in `NetworkMain`, extend `AbstractPacket` (GTNH lib).
- Do NOT add Mixins for core mining functionality; prefer the EBS/chunk-cached pure-Java helpers which are EndlessIDs-safe (`func_150818_a` / `getBlockByExtId`).
